# Method and conventions

One engine, two tracks, no tuning on test. Everything a table quotes is
reproducible from `runs/` with one command (`node results.mjs`).

## Layout

- `data/` (gitignored) — `locomo10.json`, `mab/*.parquet`, `conv/`, `longmemeval/`
- `*-vectors.json` (gitignored) — embeddings; the embedding model is named in `meta.json`
- `runs/<bench>-<split>-<config>-<reader>/` — `meta.json`, `predictions.jsonl`, `traces.jsonl`, `metrics.json`. No dates in names.
- `ablations/` — every parameter search table, dev split only
- `prompts/` — every prompt as a file; `meta.json` records its sha256
- `RESULTS.md` — generated by `node results.mjs`; never edited by hand

## Splits (declared before any search)

- LoCoMo: dev = conversations 0, 1, 2; test = 3–9. Numbers quoted before this split
  (the 22.7 → 36.2 multi-hop R@20 ALL) were on all ten and stay in the table as "all".
- MemoryAgentBench Conflict Resolution: dev = the two 6k haystacks (SH, MH);
  test = 32k, 64k, 262k. Metric: `substring_exact_match`, the benchmark's own.
- LoCoMo-Conv: the paper's protocol (all-MiniLM-L6-v2, k=10, Gemma-4-31B-it, T=0).
  Dev = the first two conversations' items; test = the rest.

## Metrics

Retrieval: R@5/10/20 ALL and ANY (gold turns), MRR of the first gold turn, NDCG@20,
candidates examined, context tokens delivered (chars/4), p50/p95 retrieval latency (ms).
Answer: token-F1 and exact match (LoCoMo normalisation), substring-EM (MAB).
Evidence grade per question: EXACT (an annotated gold turn retrieved), SUPPORTED
(a retrieved turn shares an atomic fact with a gold turn, or contains the gold answer
string), ANSWERED (the reader's answer is correct). Bootstrap 95% CI, 1000 resamples
over questions, on every headline.

## Readers

- house: `enso-flash`
- open: `google/gemma-4-31b-it` (LoCoMo-Conv's reader); fallback `qwen/qwen3-30b-a3b-instruct-2507`
- matched: the reader the compared paper used, where the router serves it (gpt-4o-mini is not served for this account; say so in the table)

Temperature 0, `max_tokens` 64, one prompt file per benchmark (`prompts/reader-locomo.txt`,
`prompts/reader-mab.txt`) shared by every row of a table. A row that changes the
reader is a different table.

Credentials: `HANZO_API_KEY`, else `~/.hanzo/credentials.json` `access_token`. Never printed.

## Rows every table carries

semantic only · +lexical · +facts · +entities · +timeline · +adjacency · +typed graph ·
+iterative hops · +deterministic resolver · full — and the failed variants: PRF,
generic multi-query, chain search, surface-entity expansion, global RRF.

## Freeze

A configuration is chosen on dev, its commit hash written into `RESULTS.md`, and the
test split run once. A later change is a new run id beside the old, never over it.
