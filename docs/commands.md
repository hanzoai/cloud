# Commands — the ⌘K bar, the CLI and Slack are one registry

## The problem

Four surfaces let a person run a Hanzo operation by name — hanzo.app's ⌘K bar,
console's ⌘K bar, the `hanzo` CLI, and Slack's `/hanzo` — and today each one
carries its own list of what can be run. Three of those lists are hand-authored
and already disagree with each other and with the API. We want one registry that
every surface reads, so a route registered this morning is a ⌘K command, a CLI
command and a Slack command this afternoon with nothing written down twice.

The registry already exists. It is `zip`'s typed-op registry, and it already has
four projections. This adds the fifth and deletes the hand-authored lists.

## What is actually there

Verified, not assumed:

- **`zip.Command` is the registry entry.** `zip/cli.go:53` — `Service`, `Name`,
  `OperationID`, `Summary`, `Description`, `Method`, `Path`, `Args []Arg`,
  `Flags []Flag`, `Example`. A `Flag` carries `Type`
  (`string|integer|number|boolean|json`) and `Required`. Path params become
  positional `Args`; the remaining `In` fields become `Flags`.
- **Two derivations already produce it.** `App.Commands()` (`zip/cli.go:110`)
  reads the registry in-process; `CommandsFromSpec([]byte)`
  (`zip/clispec.go:19`) reads it off an OpenAPI document. Both land in the same
  `Command` value and `TestCLI_SpecAndRegistryAgree` pins that they agree.
- **The document is the router.** `openapi/openapi.go:1` — the spec is projected
  from `app.Fiber().GetRoutes()`. There is no second route registry, so a
  document and the app that produced it cannot drift.
- **The fleet document is served, unauthenticated, on purpose.**
  `GET /v1/openapi.json` (`openapi/openapi.go:74`), woven by `MountFleet`
  (`cmd/cloud/main.go:550`) from the subsets 116 app binaries wrote at build.
  Its own description states the policy: *"Unauthenticated by design: a client
  has to be able to read the contract before it holds a credential, and the
  document grants nothing."*
- **2,349 operations**, `openapi.yaml` = 3,680,332 bytes.
- **Slack is live.** `POST /v1/integrations/slack/commands`
  (`apps/integrations/integrations.go:817`), HMAC-verified
  (`apps/integrations/slack_verify.go:45`, 5-minute replay window), deduped on
  `trigger_id`, org resolved by `OrgForExternalID("slack", team)`, and a
  per-user Slack↔hanzo.id link in `apps/integrations/slack_link.go`. Today
  `slackSlashTurn` (`apps/integrations/slack_events.go:265`) hands every slash
  body to the agent brain.
- **The CLI already derives from the document.**
  `/Users/a/work/hanzo/cli/src/commands/product/generated.rs` — 2,006 ops across
  70 products, generated by `src/bin/genproduct.rs` from the committed
  `spec/products.json` (823,180 bytes; 107,512 gzipped).
- **`cmdk` is not a dependency of anything.** Not in hanzo.app, not in console,
  not in chat, not in `@hanzo/ui`. hanzo.app's palette is built on `@hanzo/ui`'s
  own `Command` primitives; the word survives in one stale comment
  (`components/command-palette/index.tsx:148`). console's is 857 hand-rolled
  lines on `@hanzo/gui`.

## Constraints

Fixed:

- Auth is Hanzo IAM. The bar runs a command as the signed-in user's session; the
  CLI already holds an OIDC/PKCE token (`cli/src/iam/`); Slack maps to an
  identity through the existing per-user link. No new credential anywhere.
- The registry may not become a second source of truth. Anything it states must
  be derived from the route table, or it can drift, and a surface that drifts
  silently is the failure this whole package is built against.
- The CLI's generated tree is offline and checked in, and that is a *security*
  property: `generated.rs` is pinned to contain no host, no absolute URL and no
  auth, so a hostile snapshot can only reshape a call to your own cloud with your
  own token. It must survive.
- Chat's `/` belongs to its composer (`useHandleKeyUp.ts` — prompts and agents,
  first character only, caret at index 1).

Negotiable:

- Which surface adopts the shared bar first.
- How results render per surface.

## The design

### 1. The registry is the fleet document, projected

`GET /v1/commands` serves `zip.CommandsFromSpec(fleetDocument)` — the same
function the CLI's derivation is built on, applied to the same document every
SDK is generated from. It is a pure function of an artifact that already exists,
so it cannot carry a fact the router does not have, and it needs no new build
step, no new registry and no generator.

It is a separate address from `/v1/openapi.json` for one measured reason: the
document is 3.68 MB and a browser palette cannot load it. The command-shaped
projection of the same 2,349 operations is 823 KB, **107 KB gzipped** — 4.5x
smaller, because it drops schemas, responses and components and keeps only what
a command is. That is the whole justification; there is no second one.

It is unauthenticated, in the same words and for the same reason as the document
it derives from: a client must be able to read the contract before it holds a
credential, and a list of operation names grants nothing. Rendered once through
`sync.OnceValues` and served as bytes thereafter, so a repeat request is a memcpy
— the pattern `openapi/openapi.go:824` already uses.

**Nothing is added to `zip.Command`.** The three "surface hints" a bar wants are
already in it or already derivable:

| Bar needs | Comes from | New data |
|---|---|---|
| group | `Command.Service` — the first non-version path segment | none |
| keywords | `Command.Summary` + `Command.Description`, lifted from the handler's doc comment by `cmd/zipdoc` | none |
| icon | a `Service → glyph` map in `@hanzo/ui`, with a default | none — appearance is not meaning |

The icon map is the one thing that is written by hand, and it belongs entirely
on the client: the registry says what a command *is*, the bar decides what it
*looks like*. A missing entry falls back to a default glyph, so a new product is
never invisible.

### 2. Two kinds of executor, one type

A command that names a route runs over HTTP. A command that names a client
action — "Switch to dark theme", "Switch org", "Open project X" — runs in the
page. They are the same type at the bar; only the executor differs.

- **route**: `Method` + `Path` (fiber `:name` form) with `Args` substituted into
  the path, `Flags` marshalled into the body — or into the query when the method
  is bodyless, which the registry already distinguishes because a bodyless op's
  flags are exactly its URL-bindable fields (`zip/cli.go` `bindIn`).
- **local**: a function the surface declares. hanzo.app's existing
  `NAV_COMMANDS` (`components/command-palette/index.tsx:64`) and console's
  `PaletteAction` list (`CommandPalette.tsx:403`) are already exactly this, and
  they stay — they are the only commands with no route behind them, so they are
  the only ones that must be declared.

### 3. Authorization is the runtime's answer, never a field

`zip` has no per-op scope. It has `Authorizer` (`zip/authorize.go:26`), a hook
that runs on the decoded input of every op, over REST and MCP alike, immediately
before the handler. That is the only thing that knows whether you may run a
command, and it knows it per input, not per operation.

So the registry does not carry a scope, and the endpoint does not filter by
caller. Adding either would mean writing down a second, static claim about
permission that the Authorizer is free to contradict — which is precisely the
green surface `openapi/floor.go` and `apps/ai/mcp.go` were written against.

**The registry states what exists. The Authorizer states what you may do. The bar
renders the refusal honestly.** hanzo.app already has the one correct
translation — `refusal(status, detail)` in `lib/gateway.ts:99`: 401 is the
credential (never a login loop), 403 is permission (never "try again"), 402 is
credit, and only everything else is the service being unavailable. A command you
may not run is a sentence saying so, not a command that was hidden from you.

### 4. Safe methods browse; unsafe methods must be named

2,349 commands in one bar means typing "delete" surfaces four dozen destructive
fleet operations to someone who wanted to delete a project. The rule that fixes
this needs no second list, because `Method` is already in the registry:

- **`GET` commands match on fuzzy search.** They are safe and idempotent; browsing
  them costs nothing.
- **Every other method requires an exact prefix match on `service operation`.**
  You cannot stumble onto `POST /v1/platform/apps/:app/rollback`. You have to
  name it.

One rule, derived from data already present, and it maps exactly onto the HTTP
semantics the methods already carry.

### 5. Argument prompting

After a command is chosen, the bar prompts for its required inputs in order:
`Args` first (they address the resource), then `Flags` where `Required`. `Type`
picks the widget — `boolean` a toggle, `integer`/`number` a numeric field, `json`
a code field, `string` a text field. Optional flags are reachable but not
prompted. `Example` (already on the command, lifted from the doc comment)
prefills. No schema is written for this; it is the `In` struct, reflected.

### 6. The bar: one component, five rules

`Palette` in `@hanzo/ui`, composed from the `Command*` primitives that package
already ships (`pkgs/ui/primitives/command.tsx`), consumed by hanzo.app, console
and chat. It takes `commands`, an `onRun`, and a slot — so hanzo.app keeps its
project preview panel and console keeps its `>` AI mode without either forking
the component.

The opener rules, which are already correct in one place and need only to move:

1. **⌘K / Ctrl-K always opens it**, including from inside a text field. It is the
   universal shortcut and nothing else may claim it. chat currently declines it
   (`BrandCorner.tsx:33` passes `quickSwitchKey={false}`), so ⌘K there is free.
2. **`/` opens it only when the event target is not editable** —
   `INPUT`/`TEXTAREA`/`SELECT`/`contentEditable`. This is `isEditable` in
   `hanzo.app/hooks/useCommandK.ts:18`, already written and already correct.
3. **The chat composer conflict resolves itself.** The composer is a `TEXTAREA`,
   so rule 2 already means the global `/` never fires there, and chat's prompts
   and agents popover keeps the key it has. There is no precedence to write —
   the existing rule is the answer, and this is worth stating plainly because
   the obvious instinct is to add an exception that would be dead code.
4. **`/` typed into the palette's own input is a literal slash**, by the same
   rule — the palette input is editable.
5. **The composer's `/` menu is not merged into the bar.** It lists prompts and
   agents — content, scoped to one conversation. The bar lists operations. Two
   vocabularies, and collapsing them would make both worse.

### 7. CLI parity is a test, not a fetch

The CLI keeps generating at build. `genproduct.rs` reads `spec/products.json`,
and that file becomes the committed output of `/v1/commands` instead of a
separately-maintained snapshot. A test asserts the committed snapshot equals the
live endpoint at the pinned version.

This is deliberate and it is the one place the design refuses the obvious move.
Making the CLI fetch its command tree at runtime would give it the same freshness
the bar has, and would destroy the property that `generated.rs` contains no host,
no URL and no auth. Parity means *both are projections of one registry* — not
that both load the same bytes at the same moment.

### 8. Slack maps onto the same registry

`/hanzo <service> <operation> [args]` resolves against `/v1/commands`. Everything
it needs exists:

- **Org**: `OrgForExternalID("slack", team)`, already called in `slackCommands`.
- **Identity**: the per-user `slackUserLink` (`apps/integrations/slack_link.go`).
  The command runs as the linked person, never as the workspace — an unlinked
  user gets the ephemeral link prompt that flow already sends.
- **Auth**: the HMAC signature is the auth for the request, and the linked
  identity is the auth for the command. Both are built.

A body that resolves to a command runs it and answers with the result. A body
that does not falls through to `bridgeReply` — the agent brain, which is exactly
what happens today. Nothing regresses, and the natural-language path stays the
default.

The change is confined to `slackSlashTurn`
(`apps/integrations/slack_events.go:265`): try the registry, then fall through.

## The trade-off

**The bar shows commands the caller cannot run.** A person with no platform
grant sees `platform apps rollback` in search results and gets a 403 sentence if
they run it. The alternative is filtering the list per caller, which requires a
static scope on each op that the `Authorizer` — which decides per *input*, not
per operation — is free to contradict. That list would be right on the day it was
written and wrong afterward, and wrong in the direction that hides working
functionality from people who have access. A refused command that explains itself
is strictly better than a command that silently does not exist, and
`lib/gateway.ts` already says it in the right words.

The second cost is smaller and worth naming: **107 KB gzipped on first use.** It
is cached for the process lifetime behind an ETag, and it buys deleting three
hand-authored command lists.

## Implementation path

### Increment 1 — the endpoint, and hanzo.app's bar behind the existing ⌘K

**Derive from all of it.** The projection is total: every operation in the fleet
document, which is every app in `manifest/apps.go`. Filtering to a subset would
be the second policy this design exists to avoid. What the increment pins is
end-to-end behaviour across five named products, chosen because they are the ones
hanzo.app's own surface touches: **`projects`** (`apps/projects`, 5 route files),
**`deploy`** (`apps/deploy`, 6), **`platform`** (`apps/platform`, 4 — already the
CLI's `apps list`), **`tools`** (`apps/tools`, fully typed, pinned by
`typed_wire_test.go`), and **`o11y`** (`apps/o11y`, 9).

1. `cloud/openapi/command.go` — new, ~60 lines. `const CommandPath =
   "/v1/commands"`. A `serveCommands` that reuses the rendered document bytes,
   passes them to `zip.CommandsFromSpec`, marshals, and serves with an ETag. An
   `init()` calling `Describe(CommandPath, http.MethodGet, …)` so the command
   list is itself a command — the same self-description `/v1/openapi.json` has.
2. `cloud/openapi/openapi.go` — one edit, inside `serve()` (line 824). Both
   document sources (`Mount` for an app binary, `MountFleet` for the light host)
   go through it, so one edit lights up both, and the fleet host is the one that
   answers `api.hanzo.ai/v1/commands`.
3. `cloud/openapi/command_test.go` — new. Three pins, matching the four-projection
   discipline in `openapi/fleet.go:18`: every served command's `Method`+`Path` is
   a route the document carries; the served list equals
   `CommandsFromSpec(openapi.yaml)`; and the payload is smaller than the document
   it derives from, which is the only reason it exists.
4. `@hanzo/ui` — `pkgs/ui/components/palette.tsx`, plus `useCommandK` moved from
   `hanzo.app/hooks/useCommandK.ts` unchanged, plus the `Service → glyph` map.
   Publish as a patch bump from the current `8.0.52`.
5. `hanzo.app` — `components/command-palette/index.tsx` keeps its projects group
   and preview panel and gains a third group, `Run`, fed by `/v1/commands`.
   Execution goes through the existing gateway path so `refusal()` renders 401,
   402 and 403 correctly on day one. Delete the stale `cmdk` comment at line 148.

**Order matters and there is a landmine.** hanzo.app installs `@hanzo/ui` from
the registry, so step 4 must be published before step 5 is written against it —
a lockfile installs the old version and the consumer silently gets the previous
behaviour. This repo has paid for that mistake before.

### Increment 2 — the other surfaces

console replaces its 857-line `CommandPalette.tsx` body with `Palette`, keeping
its `>` AI mode and `?` docs mode as local commands. chat mounts it and takes ⌘K
back by dropping `quickSwitchKey={false}` in `BrandCorner.tsx:33`; its composer
`/` is untouched.

### Increment 3 — Slack and the CLI

`slackSlashTurn` tries the registry before the agent brain. `spec/products.json`
becomes the committed output of `/v1/commands`, with the parity test.

## Honest gaps

- **Prose is only as good as the doc comments.** `Summary` and `Description` come
  from `cmd/zipdoc` lifting handler comments. An op with no comment gets a blank
  summary and is findable only by its name. That is a real hole in the search
  quality, it is visible the moment the bar ships, and the fix is writing the
  comment — not adding a field.
- **Untyped routes are not commands.** A route registered outside zip's typed-op
  registry publishes an operationId and no body, and cannot become a command
  because there is nothing to derive args from. `apps/tools/tools.go:29` states
  this for `/v1/tools/plugins/build` and keeps it out on purpose. Those routes are
  absent from the bar, honestly, rather than present and broken.
- **A command's result has no declared shape for rendering.** The bar gets JSON
  back and shows it. Rendering a deploy differently from a list is per-surface
  work that this design does not do, and should not — it would be the second
  registry.

## The mental model in one line

There is one registry, it is the route table, and the ⌘K bar is its fifth
projection — after the REST routes, the OpenAPI document, the MCP tools and the
CLI.
